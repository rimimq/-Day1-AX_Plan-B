# 1차 MVP 수동 테스트 계획

## 목적

n8n 자동화 구현 전에 LLM/API 출력 품질을 먼저 검증한다. 이 단계의 목표는 기술 구현이 아니라 "BO가 쓸 만한 초안이 나오는가"를 확인하는 것이다.

## 테스트 자료

- 입력 샘플: `mvp/samples/sample-cr-input.json`
- 기대 출력 샘플: `mvp/samples/sample-ai-output.json`
- 프롬프트: `mvp/03-ai-prompt-draft.md`

## 테스트 절차

1. `sample-cr-input.json`의 `course_id`, `course_name`, `target_learning_minutes`, `bo_memo`, `cr_rows`를 확인한다.
2. `03-ai-prompt-draft.md`의 시스템 프롬프트와 사용자 프롬프트 템플릿을 후보 LLM에 입력한다.
3. `{cr_rows_json}` 위치에 `sample-cr-input.json`의 전체 JSON을 넣는다.
4. LLM 응답이 JSON 형식으로 나오는지 확인한다.
5. 응답을 `sample-ai-output.json`과 비교한다.
6. BO 관점에서 각 차시별 초안을 `사용 가능`, `수정 후 사용 가능`, `사용 어려움`으로 평가한다.

## 평가 기준

| 항목 | 기준 | 통과 기준 |
| --- | --- | --- |
| JSON 형식 | 파싱 가능한 JSON인지 | 오류 없이 파싱 |
| 근거 충실도 | CR에 있는 정보만 사용했는지 | 과도한 창작 없음 |
| 차시 구조 보존 | 차시/파트/챕터 흐름이 유지되는지 | 주요 차시 누락 없음 |
| 문체 | 운영계획서에 맞는 공적 문체인지 | BO 수정 후 사용 가능 |
| 산정사유 | 재생시간과 학습활동이 논리적으로 연결되는지 | 산정 근거가 설명됨 |
| 검토 필요 표시 | 불확실한 항목을 표시했는지 | 프로젝트/실습 후보 표시 |

## 판정 기준

1차 MVP 진행:

- BO가 "수정 후 사용 가능" 이상으로 평가한 차시가 70% 이상
- JSON 구조가 안정적으로 유지됨
- 산정사유 초안이 반복 작성 시간을 줄인다고 판단됨

프롬프트 개선 필요:

- CR에 없는 내용을 자주 생성함
- 차시별 문장이 지나치게 반복됨
- 프로젝트/실습 후보가 과도하게 탐지됨
- 산정사유가 심사 문체와 맞지 않음

시트 설계 수정 필요:

- BO가 검토해야 할 필드가 너무 많음
- 원본 CR과 초안을 비교하기 어려움
- 승인/재생성 상태 관리가 업무 흐름과 맞지 않음
