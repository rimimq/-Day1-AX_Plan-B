# Plan-B 1차 MVP PRD

## 1. 배경

KDC 온라인 과정 운영계획서는 과정별로 차시 구성, 학습내용, 학습소요시간 산정사유, 실습/프로젝트 설명 등을 반복 작성해야 한다. CR과 훈련시간계획서에 이미 과정 정보가 존재하지만, BO가 이를 운영계획서 문체에 맞게 다시 서술하는 데 시간이 많이 든다.

1차 MVP는 운영계획서 최종 문서 자동 생성보다, BO가 검토 가능한 수준의 초안을 빠르게 만드는 데 집중한다.

## 2. 목표

CR 데이터를 기반으로 운영계획서에 들어갈 과정별 변동 구간의 초안을 자동 생성하고, BO가 Sheets에서 검토/수정/승인할 수 있게 한다.

### 핵심 목표

- CR 기반 반복 서술 작성 시간을 줄인다.
- BO가 셀 단위로 초안을 검토하고 수정할 수 있게 한다.
- 승인된 결과를 다음 단계 Docs/PDF 자동 생성의 입력 데이터로 사용할 수 있게 구조화한다.

### 1차 성공 기준

- BO가 CR 기반 초안 작성에 쓰는 시간을 50% 이상 줄인다.
- AI 생성 초안 중 70% 이상이 BO 수정 후 사용할 수 있는 수준이다.
- 승인 상태값 기준으로 다음 단계 자동화가 가능한 데이터 구조를 확보한다.

## 3. 사용자

- 주 사용자: KDC BO/운영 담당자
- 협업 사용자: 교육 기획자, AX 프로젝트 담당자
- 후속 사용자: n8n/LLM API 자동화 구현 담당자

## 4. 1차 MVP 범위

### 포함

- CR 시트 데이터 입력
- 차시/파트/챕터/클립 구조 분석
- 과정 개요 초안 생성
- 차시별 학습내용 초안 생성
- 학습소요시간 산정사유 초안 생성
- 실습/프로젝트 후보 탐지 및 요약
- Sheets에 결과 저장
- 상태값 기반 BO 검토 흐름
- Slack 알림 또는 이메일 알림

### 제외

- Google Docs 운영계획서 최종본 자동 생성
- PDF 변환
- 교강사 DB 자동 추천
- HRD-Net 직접 제출
- 심사 적합성 자동 판정

### 후속 옵션

- 승인된 Sheets 데이터를 Google Docs 템플릿에 자동 삽입
- 제출 전 체크리스트 검토
- 실습/프로젝트 상세 산출물 별도 문서 생성
- 교강사 DB 기반 후보 리스트업

## 5. 입력 데이터

1차 MVP의 기본 입력은 CR이다.

필수 입력 필드:

- 과정명
- 차시
- 파트명
- 챕터명
- 클립명
- 클립 시간
- 필수강의/추가강의 여부

선택 입력 필드:

- 과정 목표
- 프로젝트 여부
- 실습 여부
- 강의자료 URL
- 커리큘럼 URL
- BO 메모

## 6. 자동 생성 산출물

### 6.1 과정 개요 초안

과정 전체의 주제, 대상 학습자, 학습 흐름, 기대 성과를 운영계획서 문체로 요약한다.

예상 출력:

- 과정 한 줄 요약
- 과정 목적
- 주요 학습 흐름
- 학습 성과
- 과정 특성

### 6.2 차시별 학습내용 초안

차시별 파트/챕터/클립 정보를 바탕으로 학습내용을 서술한다.

예상 출력:

- 차시명
- 핵심 학습내용
- 세부 학습활동
- 실습/프로젝트 포함 여부

### 6.3 학습소요시간 산정사유 초안

러닝타임과 학습활동을 바탕으로 훈련시간 산정사유를 작성한다.

문체 기준:

- "총 학습 소요 시간: 60분"
- "강의 영상 학습 및 복습"
- "실습 또는 자기주도 정리 시간 포함"
- "학습자가 개념을 실제 과제/프로젝트 흐름에 적용하는 시간 포함"

### 6.4 실습/프로젝트 후보 요약

클립명과 파트명에서 실습/프로젝트성 키워드를 탐지해 별도 검토 대상으로 분리한다.

탐지 키워드 예시:

- 실습
- 프로젝트
- 제작
- 구현
- 분석
- 자동화
- 배포
- 설계
- 제출

## 7. 워크플로우

### Step 1. CR 입력

BO 또는 기획자가 CR 데이터를 Google Sheets에 입력한다.

상태값:

- `PENDING`

### Step 2. AI 초안 생성

n8n이 Sheets 변경 또는 수동 실행을 감지해 LLM API를 호출한다.

출력:

- 과정 개요 초안
- 차시별 학습내용 초안
- 학습소요시간 산정사유 초안
- 실습/프로젝트 후보 요약

상태값:

- `REVIEW_PENDING`

### Step 3. BO 검토 및 워싱

BO가 Sheets에서 AI 초안을 검토하고 필요한 내용을 수정한다.

상태값:

- 수정 중: `REVIEW_PENDING`
- 승인: `APPROVED`
- 재생성 필요: `REGENERATE_REQUESTED`

### Step 4. 승인 데이터 고정

승인된 데이터는 2차 MVP의 Docs/PDF 생성 입력으로 사용한다.

상태값:

- `APPROVED`

## 8. 상태값 정의

| 상태값 | 의미 | 처리 주체 |
| --- | --- | --- |
| `PENDING` | CR 입력 완료, AI 생성 대기 | BO/기획자 |
| `GENERATING` | AI 초안 생성 중 | n8n |
| `REVIEW_PENDING` | BO 검토 대기 | BO |
| `REGENERATE_REQUESTED` | BO가 재생성 요청 | BO/n8n |
| `APPROVED` | BO 검토 완료 | BO |
| `ERROR` | 자동화 실패 | n8n/관리자 |

## 9. 품질 기준

AI 초안은 완성본이 아니라 BO 검토용 초안이다. 따라서 과도하게 확정적인 표현보다 검토 가능한 구조와 문체 일관성을 우선한다.

품질 체크 기준:

- CR에 없는 내용을 과도하게 창작하지 않는다.
- 차시/파트/챕터 구조를 누락하지 않는다.
- 러닝타임과 학습소요시간 산정사유가 논리적으로 연결된다.
- 실습/프로젝트성 내용은 별도 검토 가능하게 표시한다.
- 운영계획서 문체에 맞게 공적인 서술형 문장으로 작성한다.

## 10. 리스크

| 리스크 | 설명 | 대응 |
| --- | --- | --- |
| BO 실제 불편 구간 불명확 | 아직 BO 인터뷰 전이라 우선순위가 가설이다 | 1차 사용 후 필드별 만족도 조사 |
| CR 데이터 품질 편차 | 과정마다 CR 작성 방식이 다를 수 있다 | 필수 필드 검증 및 누락 표시 |
| AI 환각 | CR에 없는 내용을 생성할 수 있다 | 근거 필드 표시, 창작 금지 프롬프트 |
| 산정사유 문체 반복 | 차시별 문장이 비슷해질 수 있다 | 차시 주제별 문장 변형 규칙 추가 |
| Docs 자동화 지연 | 템플릿 매핑 난도가 높다 | 1차 MVP에서는 제외 |
