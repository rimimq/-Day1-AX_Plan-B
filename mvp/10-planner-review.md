# Plan-B 기획 점검

## 점검 기준

B2C 담당자의 요청사항을 기준으로 1차 MVP가 어디까지 반영되었는지 확인하고, 실제 업무 도구로 만들기 위해 더 필요한 부분을 10년차 기획자 관점에서 정리한다.

## 요청사항 반영 현황

| 요청사항 | 현재 반영 | 판단 |
| --- | --- | --- |
| CR을 넣으면 아웃라인 및 플로우 작성 | 과정 개요, 차시별 학습내용, 산정사유, 실습/프로젝트 후보 생성 | 반영 |
| BO가 1차 수정 및 조정 | 검토 화면, 상태값, review_comment, APPROVED 구조 | 반영 |
| 2차 산출물을 넣으면 최종 운영계획서 작성 | Docs/PDF 생성은 2차 MVP로 분리 | 후속 필요 |
| BO 최종 피드백 | 최종 피드백 상태는 워크플로우상 정의, 화면에는 후속 단계로 표시 | 후속 필요 |
| AOP 분석 과정 개요 채우기 | 과정 개요 초안 생성 | 반영 |
| 실습/프로젝트 개수, 개요, 내용, 산출물 | 후보 탐지와 예상 산출물 초안 제공 | 일부 반영 |
| 교강사 DB에서 리스트업 | 본 플로우와 성격이 달라 별도 플로우로 분리 | 의도적 제외 |
| 세부항목별 아웃라인 산출 | 과정 개요/차시/산정사유 중심으로 1차 반영 | 확장 필요 |

## 10년차 기획자 관점의 보완 포인트

### 1. 상품/과정 단위 구분

좌측 상태값은 전체 공통이 아니라 선택된 교육 상품과 과정의 처리 상태여야 한다. 이를 위해 `COURSE_INDEX`와 `product_id + course_id` 기준을 추가했다.

### 2. 4단계 요청 플로우의 가시화

담당자 요청은 단순 초안 생성이 아니라 4단계 승인 흐름이다. 화면에 `요청 플로우` 탭을 추가해 현재 MVP가 2단계, Docs/PDF 생성은 3단계 후속임을 명확히 했다.

### 3. 제출 전 체크리스트

업무 효율화가 1순위라도, BO가 최종 검토할 때 누락/불일치가 보여야 한다. `제출 체크` 탭에 과정 개요, 차시별 학습내용, 산정사유, 실습/프로젝트, 교강사, 최종문서 항목을 추가했다.

### 4. 원본 CR과 AI 초안 비교

현재 프로토타입은 초안 중심이다. 실제 MVP에서는 원본 CR 행과 AI 초안을 나란히 보여줘야 BO가 검증 시간을 줄일 수 있다.

권장:

- 차시별 초안 카드에 `source_rows` 표시
- 원본 클립명/러닝타임 펼침 영역 추가
- 초안 문장별 근거 행 표시

### 5. 변경 이력과 승인 기준

BO가 워싱한 내용은 최종 운영계획서 작성의 기준 데이터가 된다. 따라서 승인 전후 변경 이력이 필요하다.

권장:

- `approved_by`
- `approved_at`
- `draft_version`
- `previous_draft`
- `review_comment`

### 6. 실습/프로젝트 산출물의 위험도 관리

예상 산출물은 CR 기반 추정이라 환각 위험이 있다. 따라서 "자동 확정"이 아니라 "후보"로 유지해야 한다.

권장:

- `bo_decision`: `USE`, `EDIT`, `IGNORE`
- 산출물 초안은 기본적으로 `needs_review = TRUE`

### 7. Docs/PDF 자동 생성 전 템플릿 매핑

3단계 최종 운영계획서 작성은 단순 문장 생성이 아니라 양식 필드 매핑 문제다. 2차 MVP 전에 운영계획서 템플릿의 자동 삽입 필드를 확정해야 한다.

권장:

- 템플릿 필드명
- 자동 입력 가능 여부
- 필수/선택
- 데이터 출처
- BO 최종 검토 필요 여부

## 결론

현재 1차 MVP는 B2C 요청의 핵심인 `CR 기반 초안 생성 → BO 검토/승인`을 반영한다. 다만 최종 운영계획서 Docs/PDF 생성, 교강사 리스트업, 최종 피드백 루프는 1차 MVP 범위 밖으로 분리되어 있다.

다음 구현 우선순위는 원본 CR 비교, 변경 이력, 제출 전 체크리스트의 데이터화다.
