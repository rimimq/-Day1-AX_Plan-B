# BO 검토 패키지

## 목적

BO에게 기술 구현안을 설명하기 전에, "이런 초안이 나오면 실제 업무에 도움이 되는가"를 빠르게 확인한다.

검토의 핵심은 모델 종류가 아니라 산출물의 유용성이다.

## BO에게 보여줄 자료

1. 샘플 입력
   - `mvp/samples/sample-cr-input.json`
   - 실제로는 JSON 원문보다 CR 일부를 표 형태로 보여주는 것을 권장한다.

2. 샘플 출력
   - `mvp/samples/sample-ai-output.json`
   - BO에게는 아래 4개 영역만 발췌해서 보여준다.

3. MVP 흐름
   - CR 입력
   - AI 초안 생성
   - BO 수정/승인
   - 승인 데이터 고정

## BO 검토 화면에 보여줄 핵심 영역

### 1. 과정 개요 초안

검토 질문:

- 이 정도 과정 개요면 운영계획서 초안으로 쓸 수 있는가?
- 너무 마케팅 문구처럼 보이는 표현은 없는가?
- CR에 없는 내용이 과하게 들어갔다고 느껴지는가?

### 2. 차시별 학습내용 초안

검토 질문:

- 차시별 학습 흐름이 CR과 맞는가?
- BO가 직접 작성할 때보다 수정량이 줄어드는가?
- 차시명/파트명/챕터명이 적절히 반영되었는가?

### 3. 학습소요시간 산정사유 초안

검토 질문:

- 심사 제출 문체에 맞는가?
- "강의 영상 학습 및 복습" 같은 표현이 실제로 자주 쓰이는가?
- 러닝타임이 60분보다 길거나 짧을 때 표시 방식이 적절한가?
- BO가 가장 많이 수정할 것 같은 문장은 어디인가?

### 4. 실습/프로젝트 후보 탐지

검토 질문:

- 실습/프로젝트 후보를 별도로 표시하는 것이 도움이 되는가?
- 후보 탐지가 너무 많거나 적지 않은가?
- 예상 산출물 초안이 필요한가, 아니면 위험한 추정인가?

## BO 피드백 수집 양식

| 항목 | 질문 | 응답 |
| --- | --- | --- |
| 업무효율 | 이 초안이 있으면 작성 시간이 줄어들 것 같은가? |  |
| 우선순위 | 가장 먼저 자동화되어야 할 필드는 무엇인가? |  |
| 문체 | 운영계획서 문체와 맞지 않는 표현은 무엇인가? |  |
| 정확도 | CR과 맞지 않는 내용은 무엇인가? |  |
| 산정사유 | 학습소요시간 산정사유가 실무 기준에 맞는가? |  |
| 검토방식 | Sheets에서 검토/수정/승인하는 방식이 편한가? |  |
| 후속기능 | Docs/PDF 자동 생성이 꼭 필요한가? |  |

## 30분 인터뷰 진행안

| 시간 | 내용 |
| --- | --- |
| 0~5분 | 현재 운영계획서 작성 흐름 확인 |
| 5~10분 | 가장 반복적이거나 귀찮은 작성 구간 확인 |
| 10~20분 | 샘플 AI 출력 검토 |
| 20~25분 | Sheets 기반 검토/승인 방식 확인 |
| 25~30분 | MVP 범위와 후속 기능 우선순위 확인 |

## 인터뷰 후 결정할 것

- 1차 MVP 자동화 필드 확정
- 산정사유 문체 기준 확정
- 실습/프로젝트 후보 탐지 유지 여부
- Docs/PDF 자동 생성의 우선순위
- 후보 LLM 테스트 필요 여부
